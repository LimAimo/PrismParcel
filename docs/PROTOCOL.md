# PrismParcel v2 像素封装协议

> 技术说明。这里记录 v2 的当前实现，供互操作与代码审阅使用。协议尚未成为独立的正式标准。

## 数据帧（Frame）

所有无符号整数采用 big-endian（网络字节序）。以字节为单位：

| 偏移 | 长度 | 定义 |
|---:|---:|---|
| 0 | 8 | Magic：ASCII `PRSMPXL2` |
| 8 | 1 | Version：`2` |
| 9 | 1 | Flags：bit0 = encrypted；bit1 = gzip-compressed |
| 10 | 1 | Style：0 = spectrum；1 = aurora；2 = sunset；3 = graphite |
| 11 | 1 | 保留，必须为 0 |
| 12 | 4 | Payload 长度（uint32） |
| 16 | 16 | PBKDF2 Salt。未加密时全部为 0 |
| 32 | 12 | AES-GCM Nonce/IV。未加密时全部为 0 |
| 44 | 4 | 保留，必须为 0 |
| 48 | N | Payload：可能压缩、可能加密的二进制载荷 |

48 字节数据头始终为**原始 RGB 字节**，从画面左上角开始占用最前面的 16 个逻辑像素，所有色盘共用这一规则。读入时可据此确定版本、后续调色板与长度。

## 原始载荷（Plain payload）

`content || SHA256(content)`。内容字段布局：

| 偏移 | 长度 | 定义 |
|---:|---:|---|
| 0 | 1 | 类型：0 = UTF-8 文本；1 = 任意二进制文件 |
| 1 | 2 | UTF-8 文件名字节数，最多 1024 |
| 3 | 2 | UTF-8 MIME 字符串字节数，最多 1024 |
| 5 | 4 | 原始数据的字节数 |
| 9 | 可变 | 文件名 + MIME + 原始内容 |
| 末尾 | 32 | SHA-256 内容摘要 |

文字模式的 MIME 固定为 `text/plain;charset=utf-8`；其名称长度为 0。文件模式保存原始文件名和 MIME 字符串。这些字段在启用密码时与文件字节一同被加密。

## 数据处理次序

编码：

```text
原始文件 / UTF-8 字节 → 内容和元数据 → SHA-256 摘要
                                      ↓
                          可选 GZIP（若显著变小）
                                      ↓
                            可选 AES-256-GCM
                                      ↓
                            48 字节协议头 + Payload
                                      ↓
                                  像素编码 → PNG
```

解码执行相反流程。只有全部校验通过，才输出原始数据。

### 密码模式

- Web Crypto PBKDF2-SHA-256，迭代次数 **210,000**，随机 16 字节盐，输出 256 位 AES 密钥。
- AES-256-GCM，随机 12 字节 IV（每次生成重新抽取），默认 128 位认证标签。
- 当前格式不把头部作为 AES-GCM 的 additional authenticated data。头部不保密，修改头部可能导致解码失败；这不意味着可以在不知密码的情况下伪造成功解密的内容。
- 解码时认证失败统一报密码错误或数据损坏，避免以未校验的明文作为成功结果。
- 该协议不构成完整密码管理规范，且尚无独立安全审计。

### 压缩模式

先计算普通内容的 GZIP 版本，当 `gzipBytes.length + 16 < originalBytes.length` 时保存压缩版本，并设置 flags bit1。GZIP 压缩后再加密，以免无谓增大密文。解压过程限制输出大小，降低恶意压缩输入的内存风险。解压后仍检查内部 SHA-256 和长度字段。

## 像素映射

### spectrum（全色域 RGB）

从头到尾将帧字节每 3 个作为一个 RGB 像素，不足的尾部通道补 `255`；Alpha = 255。逻辑宽高由总像素量确定：

- `pixelCount = ceil(frameLength / 3)`
- `columns = ceil(sqrt(pixelCount))`
- `rows = ceil(pixelCount / columns)`

### 16 色艺术方案

前 **16** 个逻辑像素仍储存原始 48 字节数据头。Payload 中每个字节拆成高四位和低四位，各映射到颜色表的一个 **RGB 精确值**，故每个 Payload 字节占用两个逻辑像素。颜色表见 [`src/codec.mjs`](../src/codec.mjs) 中 `PALETTES`，颜色按数组下标 0–15 寻址。逻辑像素总数为 `16 + 2 × payloadLength`。

### 像素块放大

逻辑像素通过 Canvas 最近邻采样放大为 `blockSize × blockSize` 方块（UI 为 1～8，协议解码器识别 1～16）。图片文件中**不存储像素块大小**，解码器依次尝试 1～16，读取候选中心像素并匹配起始 8 字节 Magic。最后通过长度、颜色和载荷校验确保正确读取。

**重要：** 此格式要求像素颜色完全保真。PNG 的无损 RGB/RGBA 表示可使用；改变颜色值、裁剪、缩放、重采样、有损压缩等都可能使解码失败。当前**无纠错码**。

## 容量上限与未来版本

目前框架为 12 MiB，Canvas 最大 16,777,216 像素，单边最大 16,384 像素。16 色模式降低有效载荷密度；较大的 blockSize 也可能很快触及 Canvas 上限。若未来需要变动安全参数或扩展自描述头部，应增加协议版本并维护明确的迁移逻辑。
